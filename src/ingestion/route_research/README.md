# London route research ingestion (additive / isolated)

This is a **separate** ingestion package inside `src/ingestion/`. The existing
`src/ingestion/pipeline.py`, `sources/met_police.py`, `sources/osac.py`, and
`sources/tfl.py` are **unchanged**. Run the existing crawler with
`python run_test_pipeline.py` exactly as before.

## Directory structure

```text
src/ingestion/
├── pipeline.py                   # EXISTING - unchanged
├── sources/                      # EXISTING - unchanged
│   ├── met_police.py
│   ├── osac.py
│   └── tfl.py
└── route_research/               # NEW - independent
    ├── pipeline.py               # CLI runner, initializes separate workspace
    ├── sources/                  # OSM, police, TfL, ACLED, GHSL downloaders
    ├── processing/               # waypoint review, normalization, routing, parquet
    ├── legacy_tools/             # 3 earlier stand-alone scripts (optional)
    ├── seed/                     # 65 dated events, 285 named waypoints
    ├── tests/test_offline.py     # synthetic, no network
    └── requirements.txt         # install alongside main dependencies

(data generated by the new CLI)
data/route_research/
├── seed/events.csv
├── seed/waypoints.csv
├── coordinate_review.csv
├── raw/{osm,police,tfl,acled,ghsl}/
└── normalised/
```

The workspace is under existing `data/`, which the repository already ignores
in `.gitignore`. Seed files are **copied only if missing** so local edits are
not overwritten. Source seed CSVs remain versioned inside the package.

## Installation and use from the repository root

Use Python 3.11 / 3.12. First install dependencies already required by your app;
install extra packages for this ingestion module separately:

```bash
pip install -r src/ingestion/route_research/requirements.txt
python -m src.ingestion.route_research.pipeline status
python -m src.ingestion.route_research.pipeline test
```

### Essential datasets

```bash
# OSM walkable roads: GraphML, GeoJSON
python -m src.ingestion.route_research.pipeline osm

# Historical published waypoint coordinates: CSV for HUMAN review
python -m src.ingestion.route_research.pipeline geocode \
  --user-agent 'OxfordHack2026/1.0 (contact: real-email@example.com)'

# Now inspect data/route_research/coordinate_review.csv,
# and manually set accepted named places to status=approved.
python -m src.ingestion.route_research.pipeline normalize

# Generate model-ready Parquet/GeoParquet
python -m src.ingestion.route_research.pipeline export-parquet
```

### Optional contextual datasets

```bash
python -m src.ingestion.route_research.pipeline police --months 2024-10 2025-10
python -m src.ingestion.route_research.pipeline tfl

# Optional ACLED with myACLED credentials (do NOT commit credentials)
export ACLED_EMAIL='your-email'
export ACLED_PASSWORD='your-password'
python -m src.ingestion.route_research.pipeline acled --start 2020-01-01 --end 2026-10-24

# ... or using a manually downloaded ACLED CSV/XLSX
python -m src.ingestion.route_research.pipeline acled --import-file /path/to/acled.csv

# Optional GHSL requires an exact official raster URL.
python -m src.ingestion.route_research.pipeline ghsl --url 'https://...'
python -m src.ingestion.route_research.pipeline sample-ghsl --raster /path/to/tile.tif

# Next-edge demonstration, requires normalized route labels
python -m src.ingestion.route_research.pipeline next-street --lat 51.508 --lon -0.128
```

## Exactly what each script reads/writes

| CLI step | Script | Files written under `data/route_research/` | Format and granularity |
|---|---|---|---|
| `osm` | `sources/download_osm.py` | `raw/osm/london_walk.graphml`, `raw/osm/london_edges.geojson` | Directed walk graph and one GeoJSON feature per directed segment |
| `police` | `sources/download_police.py` | `raw/police/police_public_order_context.csv` | One **monthly** anonymized public order record per row |
| `tfl` | `sources/download_tfl.py` | `raw/tfl/roads_*.json`, `raw/tfl/tube_*.json` | Timestamped JSON envelopes, full road disruptions/tube status snapshot |
| `acled` | `sources/download_acled.py` | `raw/acled/london_protest_events.csv` | One ACLED **event point** per row; no trajectories |
| `ghsl` | `sources/download_ghsl.py` | `raw/ghsl/selected_source.zip` | Original raster archive exactly as downloaded |
| `geocode` | `processing/review_geocode_waypoints.py` | `coordinate_review.csv` | Place name → proposed lat/lon. Requires human approval |
| `normalize` | `processing/normalize.py` | `normalised/segments.geojson`, `segment_features.csv`, `route_segment_labels.csv`, `waypoints_approved.csv`, `review_issues.csv`, optional contextual CSVs | Roads keyed by `segment_id`, route labels by `event_id` + order |
| `sample-ghsl` | `processing/sample_ghsl.py` | `normalised/ghsl_edge_context.csv` | Raster sample by street segment |
| `export-parquet` | `processing/export_parquet.py` | `normalised/parquet/*.parquet`, `segments.geoparquet` | Columnar analytical tables; street geometries in GeoParquet |
| `next-street` | `processing/next_street_demo.py` | Prints JSON to console | Next-segment historical candidates for an input point |

Historical seed files are `seed/events.csv` (one record per announced march)
and `seed/waypoints.csv` (ordered names; not coordinates). `legacy_tools/`
contains all three scripts from the preceding route-toolkit; they're not needed
for the standard `osm -> geocode -> normalize` pipeline.

### Important provenance / limitations

- The 65 events and 285 named waypoints describe **published planned** marches,
  not observed GPS traces. The routes generated between approved waypoints are
  **shortest-path interpolations**, not historically observed street occupancy.
- ACLED event points, monthly police records, and TfL disruptions are kept in
  independent contextual tables; they **must not** be treated as movement tracks.
- Always perform date-based train/test splitting and compute features using
  **only past** events to avoid leakage.
- Live API execution and authenticated fetches have not been verified within
  this offline environment; individual offline normalizer component tests were
  supplied by the previous toolkit.
- Nominatim has usage limits. Provide a real contact in `--user-agent`, cache
  queries, and manually review ambiguous named places.

For detailed source citations and limitations, see the original research toolkit
README from the preceding deliverable. This package is a self-contained copy of
those code files and seed CSVs with a convenient project-local CLI.
